How this is counted

On each load of index.html or the sign-in page, the page sends a tiny beacon to our API. The server hashes the visitor’s IP address together with the UTC date and user-agent, using a secret that never leaves the server, then discards the IP. We store only that hash (to know if the visitor is unique today) and the counters you see here. Those hashes older than two days are deleted.

Browsers that do not send Do Not Track or Global Privacy Control also keep a random anonymous id in localStorage, or in a first-party cookie if storage is blocked. The server hashes that id with the same secret and stores the first and last UTC day it was seen — not the raw id, and not the IP. New means that id’s first day is today. Returning means it was seen on an earlier UTC day. New + Returning is that day’s identified browsers. It can differ slightly from Uniques when a hit had no id, storage was cleared, or the IP changed while the id stayed.

We do not store IP addresses. We do not use advertising cookies. We do not send this data to Google or any other analytics vendor. These totals are internal and are not published. Details are in the Privacy Policy.
